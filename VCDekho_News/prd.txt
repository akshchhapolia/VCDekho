1. Overview

1.1 What is VCDekho?
VCDekho is a platform built for founders to discover, research, and connect with venture capital firms. It provides structured profiles for VC firms — investment thesis, portfolio, team, cheque size — giving founders a single place to understand who is investing and in what.

1.2 What is the News Portal?
The VCDekho News Portal is an automated content system that publishes VC and startup funding news directly on the VCDekho website. Every article is scraped from trusted external sources, processed by an AI content engine, reviewed by the VCDekho team, and published as a formatted news article — without manually writing each piece.

The news portal serves two goals:
	•	Keep founders visiting VCDekho regularly by giving them a reason to return — fresh, relevant VC news daily.
	•	Build SEO authority for VCDekho by generating keyword-rich content that links to existing VC firm profile pages.

1.3 MVP Scope
This document covers Phase 1 (MVP) only. The MVP is intentionally narrow — the goal is to get a working pipeline live quickly, validate article quality, and then scale.

2. Data Sources

VCDekho is a platform built specifically for Indian founders, Indian VCs, and the Indian funding ecosystem. All four MVP sources are therefore India-first — publications that cover Indian startup funding as their primary beat, not as a subset of global tech news.

Source selection principle 
Every source chosen covers the Indian VC and startup ecosystem as its core focus. Global-first sources like TechCrunch or VentureBeat have been deliberately excluded from the MVP — they cover Indian funding only occasionally and inconsistently. VCDekho's edge is depth on India, not breadth across the world.

3. System Architecture

The full pipeline has five stages. Each stage is independent — a failure in one should not cascade and should be logged for retry.

3.2 Stage 1 — Scrape and fetch
A background job runs every day at 6:00 AM IST. It queries all four sources and stores the raw results in the database.

For each source:
	•	Parse the RSS feed or call the API.
	•	For each item returned, check if the source_url already exists in the raw_content table.
	•	If new: fetch the full article body (for VentureBeat, this requires an HTTP GET to the article URL). Store as a new row with status = 'raw'.
	•	If already exists: skip.
	•	Log total fetched, total new, and any errors to the job log table.

3.3 Stage 2 — Deduplicate and filter
After scraping, a second pass runs to remove noise and near-duplicates across sources.

Deduplication: Compare new items against all items from the last 14 days. If the title similarity score is above 85% (using a fuzzy match or simple token overlap), mark the newer item as status = 'duplicate' and skip it. This handles the common case where TechCrunch and VentureBeat both cover the same funding round.

Relevance filter: Score each raw item. Accept if it scores 2 or more of the following signals:
	•	Title contains a funding keyword (raise, round, seed, Series A/B/C, fund, backs, invests, VC, venture)
	•	Title contains a dollar/rupee amount ($, ₹, crore, lakh, million, billion)
	•	Source is Crunchbase (structured data is always relevant)
	•	Source is Entrackr (India-focused, always relevant)

Items passing the filter move to status = 'queued'.

3.4 Stage 3 — AI processing
Each queued item is processed by three sequential prompts sent to the Anthropic API (claude-sonnet-4-6). The full prompt templates are in Section 4.

Prompt 1 — Fact extraction: Given the raw title and body, extract: startup name, amount raised, currency, round stage, lead investor(s), other investors, country/city, industry, and one-line description of what the startup does.
Prompt 2 — Article generation: Given the extracted facts, write a 250-350 word news article in plain journalistic English. Structure: punchy first sentence, key facts in paragraph 2, investor context in paragraph 3, closing 'why it matters' line.
Prompt 3 — SEO and metadata: Given the article, generate: URL slug, meta title (60 chars max), meta description (155 chars max), 5-8 tags, and a list of VC firm and founder names mentioned (used for internal linking).

After all three prompts succeed, the item is updated to status = 'draft' and a new row is created in the articles table with all generated fields.

Important 
Each item should be processed sequentially, not in parallel, to avoid hitting Anthropic API rate limits. Process a maximum of 10 items per day in the MVP — this is well above the target of 1 article per day and gives room to discard poor quality drafts.

3.5 Stage 4 — Review queue
The review queue is an internal admin page accessible only to the VCDekho team. It shows all articles with status = 'draft' and allows:
	•	Reading the full generated article
	•	Editing the article inline
	•	Approving (sets status = 'approved', triggers Stage 5)
	•	Discarding (sets status = 'discarded', removes from queue)

The review page should show: article title, source name, source URL, draft article body, SEO slug, meta description, and tags. No other data is needed at MVP.

3.6 Stage 5 — Publish
On approval, the article is published to the VCDekho website via the Antigravity CMS. The publish action should:
	•	Create a new article record in the CMS with all fields populated (see Section 5 — Data Schema).
	•	Set the article status to 'published' and record the published_at timestamp.
	•	Resolve internal links: for each VC firm or founder name identified in Step 3 (Prompt 3), check if a VCDekho profile page exists for that entity. If it does, wrap occurrences of that name in the article body with a hyperlink to the profile page.
	•	The article is immediately live on the VCDekho website at its slug URL.


4. AI Prompt Templates

These are the exact prompts to send to the Anthropic API at each stage. Use model: claude-sonnet-4-6. Max tokens: 1000 per call.

4.1 Prompt 1 — Fact extraction
System prompt:
You are a VC and startup news analyst. Extract structured facts from
the article below. Return ONLY a valid JSON object with these keys:
startup_name, amount_raised, currency, stage, lead_investors (array),
other_investors (array), country, city, industry, startup_description
(one sentence, max 20 words). If a field is not mentioned, use null.
Do not include any text outside the JSON object.

User prompt:
Article title: {{title}}

Article body:
{{body}}

4.2 Prompt 2 — Article generation
System prompt:
You are a financial journalist writing for VCDekho, a platform for
Indian founders. Write a news article based on the funding facts below.
Rules:
- Length: 250 to 350 words
- Tone: plain, factual, no hype or jargon
- Structure: hook sentence -> funding facts -> investor context -> why it matters
- Do not start with 'In a significant...' or 'In a move that...'
- Do not invent facts not present in the input
- Do not include any preamble or explanation — output the article only

User prompt:
Startup: {{startup_name}}
Amount raised: {{amount_raised}} {{currency}}
Stage: {{stage}}
Lead investors: {{lead_investors}}
Other investors: {{other_investors}}
Country: {{country}}, City: {{city}}
Industry: {{industry}}
What the startup does: {{startup_description}}
Original source URL: {{source_url}}

4.3 Prompt 3 — SEO and metadata
System prompt:
You are an SEO specialist. Given the article below, return ONLY a valid
JSON object with these keys:
- slug: URL-friendly string, lowercase, hyphens, max 70 chars
- meta_title: string, max 60 chars, includes startup name and round
- meta_description: string, max 155 chars, compelling, includes key terms
- tags: array of 5 to 8 strings (e.g. 'Series A', 'Fintech', 'India', VC firm names)
- internal_link_entities: array of VC firm and investor names mentioned
  in the article that may have a profile on VCDekho
Do not include any text outside the JSON object.

{{generated_article}}

6. Article Page Design

Each published article lives at a URL in the format: vcdekho.com/news/[slug]

6.1 Required page elements
	•	Article headline (H1)
	•	Category badge (e.g. Funding Round, VC Firm, Founder)
	•	Published date
	•	Source attribution line: 'Source: TechCrunch' with a hyperlink to the original article
	•	Article body with internal hyperlinks to VCDekho VC profiles
	•	Tags displayed as clickable chips (links to tag-filtered news list)
	•	Related articles section (3 cards, same category or shared tags)

6.2 SEO requirements
	•	Canonical URL: vcdekho.com/news/[slug]
	•	Title tag: meta_title from the articles table
	•	Meta description: meta_description from the articles table
	•	Open Graph tags: og:title, og:description, og:url
	•	Schema markup: NewsArticle (schema.org) with headline, datePublished, author (VCDekho), publisher

6.3 News index page
A news index page at vcdekho.com/news should display all published articles in reverse chronological order. It should support filtering by category (Funding Rounds / VC Firms / Founders / Events). This page should also be SEO-optimised with a page title and meta description targeting VC and startup funding news in India.

6.4 Internal linking logic
When an article is published, the system checks the internal_link_entities array (from Prompt 3 output) against VCDekho's existing VC profile slugs. For each match, it finds the first occurrence of that entity's name in the article body and wraps it in an anchor tag pointing to the VCDekho profile.

Example: if the article mentions 'Sequoia Capital India' and a profile exists at vcdekho.com/vc/sequoia-capital-india, the first occurrence of 'Sequoia Capital India' in the body becomes a hyperlink. Only the first occurrence is linked — not every mention.


7. Admin Review Queue

The review queue is a simple internal admin page accessible only to authenticated VCDekho team members. It does not need to be polished — functional is sufficient for MVP.

7.1 Queue list view
A table of all articles with status = 'draft', showing:
	•	Article title
	•	Source name
	•	Generated at timestamp
	•	Approve button
	•	Discard button
	•	Edit link (opens detail view)

7.2 Article detail view
Clicking an article opens a detail view showing:
	•	Full article body (editable text area)
	•	Slug (editable)
	•	Meta title and description (editable)
	•	Tags (editable)
	•	Source URL (read-only link)
	•	Approve and Discard buttons

UX note 
The review queue does not need to be beautiful. A simple table with inline editing and two action buttons is sufficient. The team will spend under 2 minutes per article in the queue.
